# 大纲

## 全书体量与阶段总览
- 全书总章节数：约400章
- 目标字数：约120万字
- 全书情绪曲线：陌生与不安 → 局部可控 → 确定性持续崩坏 → 主角权限成长带来可靠爽感 → 城市级真相逼近 → 主动决定保留哪一版现实

### 阶段划分
1. 开篇期（1-50章）：建立“规则故障/维修”核心玩法；林砚从普通维修员进入秩序维护署；读者确认他可靠但绝非全知。
2. 发展期（51-270章）：跨街区、城区故障；规则互相污染；组织、旧事故、林晚线并行推进；权限从临时补丁成长到跨域兼容。
3. 高潮期（271-370章）：主协议失稳，旧版本与现行版本公开冲突；多个已埋故障回流；林砚取得版本分支权限。
4. 收尾期（371-400章）：进入根协议层，回收林晚、灰潮、现实协议来源与根规则维护者；完成最后选择。

### 各阶段节奏公式
- 开篇期：小故障立规则 → 规则违例 → 验证 → 临时修补 → 修补负债 → 更大范围同步故障。
- 发展期：多规则冲突 → 信息源互相矛盾 → 选择性合作 → 权限提升 → 旧事故回扣。
- 高潮期：城市版本分裂 → 多线回收 → 盟友/组织立场分化 → 主角决定现实分支。
- 收尾期：根因揭示 → 终局代价 → 林晚线结算 → 现实版本落定。

### 关键节点与钩子链
- 第3章：第一次成功临时补丁。
- 第5章：补丁产生意外回滚债，确认能力不是万能答案。
- 第10章：发现同一版本编号在全城多个故障中出现。
- 第50章：正式获得维护署维修权限，三年前白名单事故重新进入档案。
- 第120章：确认故障并非随机，而存在“版本回推”现象。
- 第200章：林晚留下的第一条可验证生存痕迹出现。
- 第300章：城市主协议进入双版本并存。
- 第380章：根规则真相公开。

## 卷级大纲
### 第一卷：六楼不存在（约15万字，1-50章）
- 功能：立玩法、立主角、立组织边界、完成第一次从建筑级故障到街区级同步故障的升级。
- 所属阶段：开篇期。
- 卷契约：每个异常都必须可观察、可验证；林砚靠判断和有限权限把混乱重新变可控，同时每次胜利带走新信息或新负债。
- 终局储备：本卷只解锁“临时补丁”与正式维修身份，不碰根规则、林晚最终状态和金手指上限。
- 阶段边界：可确认三年前事故编号与当前故障同源；禁止确认事故幕后与林晚生死。
- 核心事件：旧居民楼的“六楼删除”故障引出多个相同版本编号，林砚被迫从外包维修员进入官方规则维修体系。
- 起始状态 → 结束状态：只想把活干完的普通维修员 → 主动进入规则故障世界的正式维修者。

### 第二卷：错误住户（约18万字）
- 多栋住宅出现“住户身份覆盖”；林砚升级到局部回滚，开始面对人为利用规则漏洞的人。

### 第三卷：城市没有这条路（约20万字）
- 地图与交通协议分裂，跨城区故障出现；林晚旧路线第一次重新浮出。

### 第四卷：白名单（约22万字）
- 三年前事故档案全面回收；维护署内部立场分化；林砚拿到跨域合并权限。

### 第五卷：旧版本正在上线（约22万字）
- 多个旧故障统一指向“旧版本”；头号宿敌身份浮出但不完成终局解决。

### 第六卷：现实分支（约18万字）
- 主协议进入双版本并存，城市开始出现互相排斥的现实。

### 最终卷：根目录（约5万字）
- 进入根协议，回收灰潮、林晚、现实协议来源和最终选择。
