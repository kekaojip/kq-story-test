# 第一卷：六楼不存在

## 核心信息
- 章节范围：第1-50章
- 字数目标：约15万字
- 本卷定位：开篇/起步/第一次身份跃迁

## 卷契约与终局储备
- 卷契约：用具体设施故障把“规则会坏”写实；林砚靠验证和有限修补赢，不靠全知；每次解决局部问题都留下更高层问题。
- 本卷主推线：身份线——普通外包维修员 → 被观察 → 临时协作 → 正式维修者。
- 本卷战果：信息线（同步版本编号）、能力线（只读→临时补丁）、关系线（周弥从质疑到合作）、资源线（正式档案访问权）。
- 本卷解锁的终局里程碑：确认三年前“白名单事故”和当前同步故障使用同一底层版本编号。
- 本卷禁碰的终局底牌：林晚生死；灰潮真相；现实协议人为来源；根规则维护者身份；根级写权限。
- 本卷鼓励长出的：建筑级新故障、维修设备、现场验证方法、维护署内部流程和基层角色。
- 契约风险：契约安全。组织不得替林砚完成核心判断或无交换收走能力。

## 剧情单元卡

### U1：六楼不存在（第1-5章）
- 类型：规则确定性破坏 / 开篇事故
- 主推线：L2 维修权限线
- 本单元在跑的线：L1、L2、L3
- 情绪目标：熟悉设施 → 小反常 → 规则互斥 → 理性验证 → 第一次修复爽感 → 修复负债
- 核心冲突：一栋居民楼的电梯“记录上停过六楼，物理上却从未经过六楼”；被困住户正在按错误规则行动。
- 主角目标：先把人救出来，再确认到底是哪一条规则坏了。
- 关键选择：不相信显示屏、监控或住户口述中的任何单一信息源，主动制造一次可观测的空载运行。
- 收益归属：林砚完成模型、验证与补丁；周弥提供封锁与设备。
- 行动成本：林砚必须亲自进入故障电梯完成最后验证；错误补丁留下回滚债。
- 对标剧情参照：诡舍2“强开篇1-5章”的节拍A，但换成城市设施与版本冲突，不迁移具体桥段。
- 供给自查：角色、地点、能力边界已落档；无C级缺口。

### U2：没有登记的住户（第6-18章）
- 类型：身份/关系模型被证据改写
- 主推线：L1 同步故障线
- 本单元在跑的线：L1、L2、L4
- 情绪目标：以为是闹鬼 → 以为是身份伪造 → 发现“住户登记规则本身在覆盖人”
- 核心冲突：同一套房同时存在两组合法住户记录，两组人都能通过部分门禁与邻居记忆验证自己。
- 主角目标：确定谁是“错误住户”，后来转为确认问题可能根本不是某个人是假。
- 关键选择：用彼此都不知道的公共设施历史记录做交叉验证，而不是强迫选边。
- 收益归属：林砚定位“身份规则覆盖”并避免误杀/误驱逐真实住户。
- 对标剧情参照：诡舍2“姐姐妹妹”中的模型改写结构；不迁移家庭桥段。
- 供给自查：第6章起需新增两组住户和楼栋档案，属B级，可在细纲批内落档。

### U3：维修记录里的死人（第19-32章）
- 类型：信息源失真 / 人为利用规则
- 主推线：L1
- 核心冲突：维护署历史工单里出现已经死亡三年的维修员签名，而且这些工单正好覆盖当前异常点。
- 对标剧情参照：诡舍2“蝗儿沟”信息源可信度升级。

### U4：一条街两个版本（第33-45章）
- 类型：街区级规则冲突
- 主推线：L2
- 核心冲突：同一街区不同人看到不同店铺、道路和门牌版本，局部修补开始互相打架。
- 对标剧情参照：自创，沿用多层悬念与规则冲突原则。

### U5：白名单编号（第46-50章）
- 类型：卷末结算 / 长线抬升
- 主推线：L3
- 核心冲突：林砚在同步故障底层编号里发现三年前妹妹失踪事故的封存编号。
- 结算：获得正式维修身份与受限档案权限；确认旧案仍在“运行”。
- 负债：组织要求他签署更高保密级别，并暴露有人早知道这些故障会回来。

## 本卷伏笔
- F1：第1章电梯控制板出现版本号 `A-0317`，读者暂不知意义；第49章与白名单旧案对应。
- F2：第3章林砚发现自己见过类似“冲突红线”，但只记得三年前事故后曾短暂出现；第46章回收一部分。
- F3：第5章错误补丁回滚时，六楼短暂出现一扇不存在于图纸上的维修门；第30章同款门再次出现。

## 反转规划
1. “六楼故障”不是电梯坏，是楼层存在规则与编号规则冲突。
2. 第二单元“错误住户”不是某个冒牌货，而是身份规则在覆盖现实。
3. 卷末当前故障并非新灾害，三年前旧案一直没有真正结束。
